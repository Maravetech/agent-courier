# Changelog

## Unreleased

- Fix Codex-to-Claude Desktop sending: use the uniquely listed full session title instead of the unsupported `local_…` address. A one-process `ListAgents` tool gate blocks missing or duplicate Desktop targets and permits one exact `SendMessage`; success requires `msg_id`.
- Read the frontmost desktop App through `NSWorkspace`; duplicate active browser processes no longer block Codex UI delivery. Codex still blocks when it is frontmost.
- Address Claude Desktop sends by an account-scoped local session ID and refuse ambiguous name-based destinations. A running target may queue delivery; send reports acceptance, while `verify` reads the destination log. This narrows `--app claude send` to full CLI session IDs.
- Explain that a loaded new-chat home has no open conversation, while retaining the cold-start timeout refusal.
- Show the specific safe failure reason for `ui-*` errors, including UI lock timeout; hide raw CuaDriver output.
- Ignore structured Codex question answers and context injections when checking whether a delivery reply was interrupted by another user message.
- Cache the native AX Swift bridge as a source-hashed, permission-checked binary; fall back to interpreting the source if compilation or cache validation fails.

## 0.4.0

- Group pair sessions by App with shared native title/existence checks, `overlay list --json`, and explicit invalid-pair cleanup; unknown metadata does not mark a pair invalid.

- Optional macOS bird overlay anchors 2 pt before Claude or Codex sidebar conversation numbers through Accessibility. Each visible pair has two rings, one dashed line, and a transparent bird drawn from Swift vector rectangles. The bird flies for 2.5 seconds with two wing poses and Core Animation particles. Up to ten simultaneous pairs receive distinct line, ring, and bird colors; disconnected birds are gray. The resident SkyLight/Core Animation renderer does not link AppKit; it draws its own icon and opens a separate AppKit pair panel on demand. A disconnected pair blocks delivery with exit code 5. The renderer exits after the last pair disappears. Signed installation, physical icon click, and Launch at Login registration remain unverified.
- `overlay pair` supports Computer use deliveries; `ui-send`, `verify`, `wait`, and `watch` update the visual state automatically. The visual defaults off. `overlay on|off|status` shares one preference with the panel, and `COURIER_OVERLAY=0|1` overrides it for a command.
- Per-app AX rules, visible-row filtering, duplicate-frame selection, and `locate.log` track anchors. Isolated tests record the overlay PID and foreground app; key-window and physical click-through acceptance remain pending.

## 0.3.0

Fixes from an independent security review. Upgrade from any earlier version.

Breaking:

- `wait` exits non-zero when the turn was aborted, when there is no reply, or when the reply header does not match the delivery.
- `ui-send` needs the exact target session, refuses ambiguous titles, and re-reads the tab and the input box right before sending.

Changes:

- H3: UI delivery is bound to the exact session; the draft and tab are checked again after writing and before sending, so a tab switch in between stops the send and keeps the draft.
- A2: `wait` is anchored to the delivered user message instead of a wall-clock `--since`, so starting it late no longer misses a turn that has already ended.
- A3: `watch --stream` prints one line per state change (started, completed, aborted, waiting) for callers that run it in the background.
- M1: Aborted turns and malformed or mismatched reply headers no longer count as success.
- Multi-line input box values read through accessibility are decoded before the draft check.
- M5: CI actions pinned to commit SHAs, with `permissions: contents: read`.
- L1: README, SKILL.md and PREREQUISITES.md match the code.
